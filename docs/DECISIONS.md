## D-01. 프로젝트 방향
- 날짜: 2026-09
- 결정: 마취과 전문의 한 명의 다중 수술방 감독 보조 시스템 (시뮬레이션 수준)
- 이유: 대형 병원 마취 전문의 부족으로 한 명이 여러 방을 책임지는 상황을 보조. 교수님도 시뮬레이션 수준까지를 범위로 봄
- 원칙: 한 방에 한 명이라는 원칙을 대신하는 도구가 아니라, 이미 벌어지는 상황의 위험을 줄이는 보조 도구. 투약·처치 결정은 범위 밖
- 시연: 2026년 12월 학기 말

## D-06. 케이스 선정 방법
- 날짜: 2026-09-29
- 1차 (폐기): 수술 중 전체 비율 기반 → 원래 혈압이 낮은 환자까지 저혈압으로 잡혀 폐기
- 2차 (채택): "직전 15분 정상 → 이후 이탈 지속" 사건 탐지, 후보 1,000개 무작위 추출(random_state=7) 중 787개 분석

  - BIS 이탈: 직전 BIS 중앙값 55 이하 → BIS 65 이상 3분 이상 (수술 종료 20분 전 이후는 각성기라 제외)
  - 잡음: SQI 50 미만 2분 이상
- 이후 그래프로 사람이 직접 검증
- 주의: 이 기준은 "확실한 사건 케이스를 고르기 위한 엄격한 기준"이며 알람 기준이 아님 (D-09 참고)
- 실행 순서: data/scripts/ 의 1 → 2b → 3 → 4 → 5 → 6 (2a는 폐기된 1차 방식 기록용). 모두 저장소 최상위에서 실행, 중간 결과는 data/work/

## D-08. 데이터 파일 형식 (2026-09-30 갱신)
- 결정: 수술 전체 길이를 받는다 (README의 "시작 지점 조절" 기능을 위해)
- 결정: 신호 종류별로 나눠 parquet(zstd 압축)으로 저장, 케이스마다 5개 파일
  - case_<id>_num.parquet: 1Hz 수치 (BIS·SQI·EMG·SR·SEF, 혈압, HR, SpO2, EtCO2, 체온, 호흡수, FiO2, 호흡량, 환기량, PEEP, 최고 기도압, MAC, 약물 농도)
  - case_<id>_eeg.parquet: 128Hz 뇌파 (EEG1, EEG2)
  - case_<id>_wave.parquet: 500Hz 파형 (ECG II, ART, PLETH)
  - case_<id>_vent.parquet: 100Hz 호흡 파형 (CO2, 기도압) ← 2026-09-30 추가
  - case_<id>_meta.json: 방 배정, 이상 시점, 시연 start, 빈 열 목록
- 모든 파일의 t 열 = 케이스 기록 시작부터의 초 (재생기 start와 같은 기준)
- 용량: 6개 케이스 합계 약 195MB
- 받는 법: pip install -r requirements.txt → 저장소 최상위에서 python data/scripts/6_download_cases.py

## D-09. 알람 기준 (3단계 색 체계)
- 날짜: 2026-09-29
- 두 층 구조:
  - 1층 (기존): 각 수술방 모니터는 지금처럼 즉시 울림. 이 시스템은 1층을 대체하지 않음
  - 2층 (이 시스템): 여러 방을 맡은 전문의에게 보여줄 순위의 기준. 아래 표
- 결정:

| 항목 | 노랑 | 빨강 |
|---|---|---|
| MAP | 65 미만 1분 이상 | 55 미만 (즉시), 또는 55 미만 누적 10분 |
| BIS | 40~60 이탈 1분 이상 | 이탈 5분 이상 |
| SpO2 | 90 미만 2분 이상 | 85 이하 2분 이상 (변경 제안 있음, 아래 "논의 중" 참고) |

- 잡음 처리: SQI 50 미만이면 BIS 판정 보류, 동맥압 20 미만 또는 200 초과는 잡음으로 처리
- 근거:
  - MAP 노랑: 수술 중 저혈압의 일반적 정의 (MAP 65 미만 1분 이상)
  - MAP 빨강·누적: AlertWatch OR 기본값 (Tremper KK et al. BMC Anesthesiology 2018;18:16)
  - BIS: 일반 목표 범위 40~60. 빨강 기준은 팀 결정
  - SpO2: Ehrenfeld JM et al. Can J Anesth 2010;57:888-897 (마취 95,407건, 저산소증 = SpO2 90 미만 2분 이상, 심한 저산소증 = 85 이하 2분 이상)
  - 지속 시간을 두는 근거: 기준값만 쓰면 경보의 71.8%가 임상적으로 무관했고, 지연 시간을 두자 경보가 진짜일 확률이 28% → 46%로 오름 (Schmid F et al., 2015). 2023년 부인과 수술실 연구(수술당 경보 평균 11.7회)도 지연 시간 도입을 권고
- 주의: "1분", "2분"은 원래 연구에서 사건을 정의하는 기준이며, 2층(순위)에만 적용함. 1층(방 안 모니터)의 즉시 경보는 그대로
- 변경 이력: (이전) SpO2 노랑 94 미만 30초, 빨강 90 미만 → 근거 부족으로 문헌 기준으로 교체 (2026-09-29)

## D-11. 재생기 구조 (A안: tick 방식 클래스)
- 날짜: 2026-09-29
- 결정: tick()을 부를 때마다 가상 시간 1초를 전진시키고 4개 방의 1초치 데이터(Frame)를 돌려주는 파이썬 클래스

## D-12. 수치 빈칸 처리
- 날짜: 2026-09-29
- 사실: 환자 모니터 수치(MAP, HR, SpO2)는 약 2초마다, 마취기 수치는 약 7초마다 기록되어 1초 기준으로 빈칸이 많음
- 결정: 실제 모니터처럼 마지막 값을 유지하고 age(경과 초)를 함께 전달. 10초(HOLD_S) 넘게 새 값이 없으면 None
- 이유: None은 "신호 끊김"을 뜻하며 수치 0과 구분됨

## D-13. 관련 연구 사실 확인
- Anesthesiology Control Tower: 미국 세인트루이스 워싱턴대(WashU). ACTFAST(NCT02830126), TECTONICS(NCT03923699)
  - TECTONICS 결과 (Br J Anaesth, 2024): 수술 71,927건 무작위 시험에서 관제탑 지원이 30일 사망·호흡부전·급성 신장 손상·섬망을 개선하지 못함
  - 우리와의 차이: 그쪽은 정상 인력에 원격 감시를 더해 환자 결과 개선을 노림. 우리는 이미 한 명이 여러 방을 맡는 현실에서 "놓치는 순간"을 줄이는 것이 목표이며, 직접 측정 가능한 지표(가짜 경보 감소율, 탐지 시간)로 평가
  - 주의: "한 명이 여러 방을 봐도 결과가 같다"는 주장의 근거로 쓰면 안 됨 (그런 비교를 한 연구가 아님)
- 서울아산병원 저혈압 예측 AI: IEEE Transactions on Neural Networks and Learning Systems, 2023. 판단 근거 제공은 사실로 확인
- 한국 현실 근거:
  - 마취통증의학과 전문의 5,453명 중 종합병원급 이상 1,867명(34%), 의원 47% (보건복지부, 2024.8)
  - 전공의 이탈 후 수술방 40~50% 폐쇄, 가장 큰 이유가 마취과 인력 부족이라는 보도 (중앙일보 2024.8, 복지부 설명자료가 인용)
  - 인력 부족 병원에서 전문의 1명이 여러 수술방을 맡는 경우가 있다는 보도 (메디게이트뉴스, 2023). 빈도에 대한 공식 통계는 없음
  - 2026년 1월 강남 개인병원 사건: 프리랜서 마취의가 마취 후 다른 병원으로 이동, 환자 심정지 (2026년 5월 수사 착수, 판단 전)

## D-14. 재생기 확인 화면 (2026-09-30 수술방 모니터판으로 교체)
- 구성: 위 "중앙 감시"(4개 방 타일), 아래 선택한 방의 "수술방 모니터"(파형 5개 + 주요 수치 + BIS 뇌파 모듈 + 마취기·약물)
- 생성: 저장소 최상위에서 python -m replay.export_viewer → replay/viewer.html (약 7MB, 시연 16분만 담음)
- 16분만 담은 이유: 시연이 15분이고, 수술 전체를 담으면 100MB를 넘어 열 수 없음. 재생기 자체는 수술 전체를 재생함
- 뇌파 성분 계산 (export_viewer.py):
  - 파형: 4차 버터워스 대역 통과 필터(scipy sosfiltfilt, 위상 지연 없음)
  - 비율: 매초 직전 4초 구간의 Welch 주파수 분석, 1~30Hz 전체 대비 %
- 화면의 모든 값은 VitalDB 실제 트랙에서 가져옴. 계산한 것은 뇌파 성분(델타·알파·베타)과 그 비율뿐. 약물 농도는 주사 펌프가 계산한 추정값(Orchestra/*_CE)
- 이 화면은 "확인용"이며 감시 에이전트는 적용하지 않음. 주황 표시는 지속 시간을 따지지 않은 원시 기준 초과

## D-15. 에이전트의 의미
- 이 프로젝트의 에이전트는 AI가 아니라 "보고 → 판단하고 → 알리는" 역할 단위의 파이썬 클래스
- 판정은 규칙 기반 (이유를 설명할 수 있어야 하므로). AI는 예측·요약 같은 보조 기능에만
- 구성: 방별 감시 에이전트 4개 (방마다 1개) + 중앙 감독 에이전트 1개
